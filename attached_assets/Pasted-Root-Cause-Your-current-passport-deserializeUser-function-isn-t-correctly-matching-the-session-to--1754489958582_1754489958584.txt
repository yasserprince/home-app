Root Cause
Your current passport.deserializeUser() function isn't correctly matching the session to a user. That’s why:

The session exists (connect.sid cookie is present).

But req.user is undefined, meaning the user isn’t restored into the session.

So protected endpoints return 401 Unauthorized.

✅ Fix Summary
You need to:

Ensure passport.deserializeUser() is implemented and correctly linked to your database.

Verify the middleware order in server/index.ts so that:

session → passport.initialize() → passport.session() → routes.

Adjust replitAuth.ts to be less strict initially and include logging for debugging.

✅ Step-by-Step Fix
1. ✅ server/auth/passport.ts (or similar)
Make sure you have both serialize and deserialize implemented:

ts
Copy
Edit
passport.serializeUser((user: any, done) => {
  done(null, user.id); // Store user ID in session
});

passport.deserializeUser(async (id: string, done) => {
  try {
    const user = await db.query.users.findFirst({ where: { id } }); // Replace with your DB lookup
    if (!user) return done(null, false);
    return done(null, user);
  } catch (error) {
    return done(error, null);
  }
});
🔁 Adjust DB query depending on whether you're using Drizzle or Prisma.

2. ✅ server/index.ts – Middleware Order
Ensure middleware order is exactly:

Make sure passport.session() comes after session() and passport.initialize().

3. ✅ server/replitAuth.ts – Add Fallback Logging
Update your isAuthenticated middleware:

ts
Copy
Edit
export const isAuthenticated: RequestHandler = async (req, res, next) => {
  const user = req.user as any;

  console.log("🔐 Auth Check:", {
    hasSession: !!req.session,
    hasUser: !!req.user,
    sessionID: req.sessionID,
    cookies: req.headers.cookie,
  });

  if (!user) {
    return res.status(401).json({ message: "Unauthorized" });
  }

  next();
};

✅ Final Notes
This issue is not related to CORS anymore. It’s purely passport session deserialization failure.

Ensure your SESSION_SECRET is present in Replit secrets.

Avoid mixing file uploads with failed authentication – always check req.user first.
